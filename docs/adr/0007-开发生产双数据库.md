# 0007 — 开发/生产双数据库隔离

**状态：** 已采纳  
**日期：** 2026-05  
**决策者：** 板儿面

---

## 背景

开发和调试时经常需要测试爬虫、修改数据、调整匹配逻辑。直接在 `cigars.db`（生产库）上操作风险极大——删错一条快照、改错一个价格，直接影响生产数据。

## 选项

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A: 单库 | 只有一个 cigars.db | 简单 | 开发误操作直接污染生产 |
| B: 双库 .env 切换 | 通过 `DJANGO_DEBUG` 切换 DB 文件 | 隔离安全 | 两套数据需手动同步 |
| C: Docker + 独立实例 | 开发用 Docker 起干净环境 | 完全隔离 | 太重 |

## 决策

**选 B：通过 `DJANGO_DEBUG` 环境变量切换。**

- `DJANGO_DEBUG=True` → `cigars_dev.db`（开发库）
- `DJANGO_DEBUG=False` → `cigars.db`（生产库）
- 两个 `.db` 文件都在 `.gitignore`，不进版本控制

## 后果

**好处：**
- 开发时随意操作不影响生产
- 切换只需改 `.env` 一行（`DJANGO_DEBUG=True/False`）
- 无需 Docker、无需维护两套环境

**代价：**
- 两个 DB 数据可能不同步（dev 库可能比生产旧）
- DEBUG=True 时 Django 会泄露调试信息（本地安全，不影响服务器）
- 需要记得切回 False 再操作生产
