# 0010 — Stock Movement 作为库存事实源

**状态：** 已采纳
**日期：** 2026-06-15
**决策者：** 板儿面

---

## 背景

订单和库存系统需要给 agent 暴露写数据接口。agent 可能重复提交、补录历史订单、取消订单或做库存修正；只保存 `PurchaseBatch.remaining` 这类当前余额，无法解释“谁在什么时候为什么改变了库存”，也无法可靠重放或修复错账。

## 决策

库存事实源采用 `Stock Movement`。每一次入库、预留、出库、释放预留和库存修正都写入不可变库存流水；`PurchaseBatch.remaining` 继续保留为当前库存读模型，用于现有库存页面和快速查询。

销售单采用两阶段库存语义：`pending_payment` 创建 `Stock Reservation`，`paid` 将预留转为正式出库，`cancelled` 释放预留。

## 后果

**好处：**
- 库存、订单、利润报表有可审计依据。
- agent 重试或补录时可以通过幂等键和流水检查避免重复扣减。
- 当批次余额与流水不一致时，可以写校验和重算命令修复读模型。

**代价：**
- 所有库存写入必须走服务层，不能直接改 `PurchaseBatch.remaining`。
- 需要维护流水与读模型之间的一致性。
- 历史订单缺少批次分配信息，需要作为历史数据单独处理。
