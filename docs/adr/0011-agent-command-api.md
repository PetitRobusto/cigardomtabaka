# 0011 — Agent 只使用命令式业务接口

**状态：** 已采纳
**日期：** 2026-06-15
**决策者：** 板儿面

---

## 背景

订单和库存系统会暴露给根 agent 使用。若 agent 能直接 CRUD `PurchaseBatch`、`SalesOrder` 或 `SalesOrderItem` 字段，就可能绕过库存流水、批次分配、幂等检查和报表口径，导致库存不可审计。

## 决策

Agent API 只暴露命令式业务动作，不暴露通用模型 CRUD。典型命令包括创建采购单、确认入库、创建销售单、确认付款、取消销售单、库存修正和生成业务报表。

每个会改变业务数据的命令都必须记录动作时间、真实业务责任人 `Operator`，以及实际执行命令的 `Agent` 信息。`Agent` 信息至少能区分来源和运行实例，例如 agent 名称、run id 或 request id。业务记录通过服务层写入 `Stock Movement`、`Stock Allocation` 等模型。

## 后果

**好处：**
- agent 无法直接修改库存余额或订单状态，库存一致性由服务层维护。
- 审计记录能回答“谁让哪个 agent 在什么时候通过什么命令改变了数据”。
- 幂等、权限和校验规则集中在命令入口。

**代价：**
- 新增业务动作时需要显式增加命令接口。
- 简单字段修改也不能绕过服务层，开发上更严格。
