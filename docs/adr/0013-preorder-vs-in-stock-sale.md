# 0013 — 预售与现货销售分开处理

**状态：** 已采纳
**日期：** 2026-06-15
**决策者：** 板儿面

---

## 背景

预售是常见业务场景，但库存系统也需要记录真实现货。如果现货销售允许负库存，库存报表、利润计算和批次追溯都会变得不可靠。

## 决策

现货销售不允许负库存。创建或预留现货销售单时，Available Stock 不足则命令失败，并返回缺货明细。

预售作为独立业务路径处理。预售不占用 `Purchase Batch`，不创建 `Stock Allocation`，也不影响 Available Stock；到货后再通过明确命令转为可分配库存或关联后续履约。

## 后果

**好处：**
- 现货库存始终可信，不会被预售订单拉成负数。
- 报表可以分开展示现货销售、预售订单和可售库存。
- agent 在库存不足时能明确选择：换货、减少数量，或创建预售。

**代价：**
- 销售接口需要区分现货与预售。
- 预售履约需要单独状态和后续转化动作。
