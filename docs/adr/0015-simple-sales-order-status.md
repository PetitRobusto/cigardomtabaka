# 0015 — 保留简单 Sales Order 状态

**状态：** 已采纳
**日期：** 2026-06-15
**决策者：** 板儿面

---

## 背景

混合现货和预售后，理论上可以把销售单拆成付款状态和履约状态。但当前系统目标是让 agent 可靠记录订单和库存，过早引入双状态机会增加接口、迁移和操作复杂度。

## 决策

第一版保留一个简单 `Sales Order` 状态，不拆 `payment_status` 和 `fulfillment_status`，也不为突发情况扩展大量临时状态。库存变化不依赖直接修改订单状态，而由明确命令驱动：创建销售单时预留现货，确认付款时正式出库，取消时释放预留；预售明细通过 `Fulfillment Type` 与现货明细区分。

特殊情况通过订单备注记录，例如客户临时换货、代取、拆单发货、等待人肉带货、部分商品延迟等。备注用于解释上下文，不承担库存事实源职责。

## 后果

**好处：**
- 状态模型简单，适合 agent 通过自然语言操作。
- 迁移成本低，能沿用现有 `SalesOrder.status`。
- 核心库存一致性仍由命令和库存流水保证。
- 突发业务情况可以记录在备注里，不需要不断新增状态。

**代价：**
- 复杂场景下订单整体状态不表达所有细节。
- 报表需要结合销售明细、库存分配和库存流水判断部分履约。
