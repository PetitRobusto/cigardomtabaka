# 0016 — 用 Order Event 记录订单操作备注

**状态：** 已采纳
**日期：** 2026-06-15
**决策者：** 板儿面

---

## 背景

销售单已有 `note` 字段，适合作为当前备注给人快速查看。但 agent 会持续追加业务上下文，例如客户改自提、代取、换货、拆单、延迟等；只覆盖一个备注字段会丢失变化过程。

## 决策

保留 `SalesOrder.note` 作为当前订单备注，同时新增 `Order Event` 作为追加式操作日志。每次 agent 或人工执行写命令时，可以附带一条备注；事件记录时间、Operator、Agent、命令名和备注内容。

`Order Event` 不承担库存事实源职责。库存数量变化仍由 `Stock Movement` 记录，订单事件只记录业务沟通和操作上下文。

## 后果

**好处：**
- 突发情况可以持续追加记录，不需要新增订单状态。
- 可以追溯谁在什么时候通过哪个 agent 改了订单背景。
- 当前备注和历史备注分工清楚。

**代价：**
- agent 写命令时需要多带一个可选备注参数。
- 订单详情页和报表若要展示历史背景，需要读取事件日志。
