# 0017 — Agent 写命令必须幂等

**状态：** 已采纳
**日期：** 2026-06-15
**决策者：** 板儿面

---

## 背景

Agent 可能因为网络超时、上下文恢复、重试策略或人为重复指令而再次提交同一个写命令。订单和库存命令一旦重复执行，可能重复创建订单、重复预留库存或重复出库。

## 决策

所有 agent 写接口必须携带 `idempotency_key`。推荐格式为 `<agent_run_id>:<command_name>:<local_step_id>`，例如 `run_20260615_001:create_sales_order:step_03`。

服务端保存幂等键、命令名、请求摘要和第一次执行结果。重复收到同一个键时，如果请求体一致，直接返回第一次结果；如果请求体不一致，返回冲突错误，要求 agent 更换键或显式解释原因。

## 后果

**好处：**
- agent 重试不会重复扣库存或重复创建订单。
- 可以追溯某个业务动作来自哪次 agent run 和哪一步。
- 幂等冲突能暴露“同一个动作编号被用于不同请求”的错误。

**代价：**
- 每个写命令都需要保存幂等记录。
- agent 调用协议必须稳定生成并传递幂等键。
