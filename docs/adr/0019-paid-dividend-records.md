# 0019 — 已支付分红一次登记

**状态：** 已采纳
**日期：** 2026-10-19

## 背景与需求契约

日常只需补记已经实际支付的分红，并在账务工作台明细表格查看。现有先分配、再逐人领取的交互增加了不必要的步骤。

## 决策

- 新增“记录已支付分红”命令：总额、两位不同的启用用户、一个启用公司人民币付款账户、实际支付日期、选填备注。沿用按分精确各 50% 的规则。
- 正常一次保存；服务端在同一数据库事务中创建分配和两笔全额领取。任何一步失败全部回滚，不发起真实转账。
- 公司现金和未分配利润各减少总额，待付分红净变化为零，经营净利润不变。
- 利润不足返回只读警告及绑定完整请求、操作人和利润快照的指纹；用户明确确认后才能保存。利润变化要求重新确认。
- 根幂等键标识整笔登记，子领取键由根键稳定派生；完整请求摘要和不可变事实用于重放核验，网络失败重试不重复扣款。
- 前端不要求单独预览；只有警告显示确认。提交期间冻结输入；不确定失败保留原请求用于重试，成功后清空金额和备注，沿用人员及账户。
- 下方新增按月分页的分红明细，一轮一行，可展开付款明细。按分配日期或实际领取日期落在月份内纳入历史轮次，并明确展示分配日期、支付日期及待领状态，不把跨月轮次总额当本月支出合计。
- 默认人员与账户来自最近登记且当前仍有效的事实，不任意猜选合伙人。历史未领完轮次保留领取操作；旧 A/B 记录保留只读。

## 实现边界与验证

复用 DividendRound、DividendPayout 和现有账务分录，无需数据迁移，不改写历史事实。新命令由工作人员 JSON API 暴露。更新业务词汇及帮助引导。

验证现金、利润、待付不变量，第二笔领取失败回滚、余额不足、历史余额保护、权限、精度、用户与账户有效性、警告快照、幂等冲突及并发重复提交。前端覆盖正常单次保存、异常重试、警告确认、按月表格和历史领取。

视觉预览使用既有 CigarDomTabaka 设计项目中的独立运行，产物为 `finance-paid-dividends-20261019.html`，沿用 `brand-spec.md`；分红录入保留在现有动作区，记录移至下方独立明细表格。分红面板首次打开后持续挂载，避免切换操作页签丢失未确认请求及原警告指纹。
