# 0019 公开目录使用 React 构建阶段预渲染

状态：已采纳并在第一期实现，本地验证后按发布流程上线。

日期：2026-10-19。

## 背景

中文目录此前依赖 JavaScript 获取数据和正文。SEO 第一期需要让 Google、Yandex 和未执行 JS 的访客直接读取门店、品牌与型号资料，并保持内部业务系统的 React 交互及访问边界。

## 决定

在现有 React 页面上生成首批 20 个公开页面，构建阶段使用 React 服务端渲染，浏览器通过 hydrateRoot 接管相同组件和公开查询缓存。复用当前路由、目录组件、导航和品牌样式，不新增 Django 产品模板，也不引入常驻 Node 服务。

本决定扩展 [ADR 0006](0006-django-react-混合架构.md) 的统一 SPA 空入口：产品 UI 继续在 React，Django 负责 JSON API 和入口响应，但重点公开入口可以返回构建好的 React HTML；其他有效页面保留 SPA 行为。

构建输入为版本管理的公开目录快照和编辑文案。导出支持明确的开发数据库，或固定本站公开 API 的匿名 GET。构建本身不请求生产服务、不读取数据库和登录态。快照禁止价格、成本、库存、客户、密码及 token 等字段。

公开 HTML 写入仓库根的 `.seo-rendered/`，位于 Django static 和 media 之外。CI 将其与前端资源按同一 commit SHA 打包；安装时分别写入公共资源目录和私有 HTML 目录，任一替换失败时回滚两者。Django 只在正式公开 URL 上返回这些 HTML，不对外提供构建文件路径。

入口先检查实体存在及软删除状态，再检查内容配置、页面清单、HTML 校验和与对应公开 API payload 的 fingerprint。有效且一致才返回预渲染内容；不一致时保留在线目录可用性并回退 SPA，通过 `X-CDT-Rendering` 区分。`check_public_seo` 在验收中检查全部重点 URL，任何静默降级都应被报告，并按刷新流程重建。

所有用户与搜索引擎接收相同公开内容。私密文档、登录、业务页面及 API 保留原有权限控制，并设置适用的排除索引指令。预渲染不包含用户登录状态，也不生成客户 token 页面。

## 取舍

构建阶段预渲染适合当前更新频率较低的目录和门店资料，能复用现有组件及 CI。公开目录修改后需要同步快照并重建；在重建之前相关页面可能回退 SPA。该状态必须通过检查命令发现，不能当作 SEO 验收通过。

型号详细页中的相关型号列表改为稳定排序，保证快照可比较。后续若公开内容高频更新或构建规模显著增大，再按实际测量评估增量生成或 SSR。

刷新与账号配置步骤见 [SEO 运维与验收](../seo-operations.md)。
