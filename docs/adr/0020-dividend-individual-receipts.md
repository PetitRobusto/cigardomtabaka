# 0020 — 按个人实领金额登记分红

**状态：** 已采纳
**日期：** 2026-10-20

## 需求契约

用户填写一位合伙人实际领取的金额，系统按各 50% 自动确认两人的同额份额。另一人未领取的部分记录为待领，仍留在公司账户，可用于正常经营，不冻结或预扣资金。

例如个人实际领取 5000 元：总分配 10000 元，现金减少 5000 元，另一人待领 5000 元；未分配利润减少 10000 元。以后补领仅减少现金与待付，不再次分配利润。

## 决策

- 表单以个人实领金额为输入，自动计算两人总分配。选择实际领取人、另一位合伙人、公司人民币账户及实际支付日期；同一天确认分配与本次支付。仅有两位启用用户时自动匹配另一人，不能猜选多人场景中的另一位合伙人。
- 默认另一人未领取；勾选“另一位合伙人也已领取同额分红”可一次记录双方全额领取。成功后清空金额、备注并重置勾选，避免沿用上次付款状态。
- 显示本次扣款、另一人待领、总分配及不冻结资金的含义。已有分红的补领从明细中进入，避免重新建立份额。
- 扩展已有原子命令：可选 `partner_a_paid_cny` 与 `partner_b_paid_cny` 必须成对提供，分别在零至每人应分之间，至少一人实领大于零；零元不创建付款事实。两字段均省略兼容原来的全额行为和请求指纹。
- 未分配利润与超额警告按总分配判断；当前及历史账户余额按实际付款判断。根事务覆盖分配与全部非零付款，失败全部回滚。
- 请求指纹与警告包含实际领取金额。重放验证本次派生付款键及不可变事实，允许同轮后来发生独立补领；缺失或损坏的本次子事实拒绝重放，不补造。
- 不新增模型、冻结余额或迁移，不改写历史事实，不改变经营净利润。
