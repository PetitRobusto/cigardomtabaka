# 0024 — 其他收入按原币收款、人民币核算

**状态：** 已采纳
**日期：** 2026-11-02

## 需求契约

公司除商品销售以外也会取得利息、旧物出售等收益，实际收款可能是卢布。人民币统一核算不意味着所有收款必须为人民币。入口复用费用登记区域，费用和收入分别展示。

## 决策

- 增加不可变的 OtherIncome 和 OtherIncomeReversal 事实，经独立业务命令原子地追加收入事实及平衡分录。保存原币、人民币、业务日期、汇率及来源、操作人、Agent 来源、幂等键和凭证参考。
- 第一版只支持收益确认与到账同日的 CNY/RUB 收入。旧物必须确认已费用化且账面价值为零，尚不覆盖非零账面资产、应计未收或跨日收款。
- 卢布以业务日手填汇率 `1 CNY = X RUB` 折算，Decimal 四舍五入到分。账户原币和人民币账面成本同时增加，后续支出按已有移动平均规则。前端精确预览仅辅助确认，入账金额以服务端为准。
- 存款利息、旧物出售、其他收益单列科目，经统一利润事实入口纳入净利润、未分配利润和分红依据，不改变销售业绩、销售排行或主营成本占比。
- 冲正使用原币与原人民币金额，禁止有后续账户流水或原日期已被对账覆盖的直接冲正。卢布补录不能越过更晚业务日期的账户流水。既有通用冲正入口不放行此新类型。
- 写入使用现有账户锁、SQLite 写门及重试；一致重放验证完整事实和分录，不重复入账。已冲正事实不能通过原创建键再入账。迁移只增加模型和科目选项，不变更旧事实。
- 前端发送前持久保存按用户分区的待确认内容和 UUID 幂等键；Web Locks 协调多标签读写。刷新后恢复同一笔请求，结果未知时固定内容供重试；无安全锁或存储不可用时不发起新写入。旧响应只清理对应键，避免覆盖后续请求。
- 两级业务分类由前后端共享目录定义，新增不可变 `subcategory` 和 `recognition_confirmed`，一级由二级唯一确定。保留原三个会计归集科目及历史空子分类；投资利息和投资分红归其他收益。新写入必须带有效细分及相应声明，复杂资产/汇兑类型由命令层拒绝。
- 旧版已提交但未收到响应的请求可以按原键及原字段重放，历史默认空子分类不被回填。尚未入账的旧版请求确定性拒绝，前端解除挂起后由用户重新选择细分再确认。迁移仅增加字段，不改历史金额和分录。

## 验证

人民币/卢布、汇率方向与精度、移动平均后续支出、跨月冲正、利润口径、权限、历史日期和对账边界、并发幂等、回滚、不可变性及迁移正反向测试。UI 先使用既有设计项目与品牌规范，经 Claude Code 独立 run 生成预览，再接入 React。
