# 预售到货自动预留

> 后续规则已调整：取消手动备货，自动预留后直接出库。当前规则见 [直接出库计划](preorder-direct-shipment-plan.md)。以下保留阶段性设计与验证记录。

用户于 2026-10-21 明确选择：到货后即应计入已预购并从可售库存扣除；备货只确认拣货，不重复预留。

## 实现契约

- 延续当前 feature branch，保留此前改动；本轮仅本地，不推送或部署。
- 采购到货事务中，在入库和状态落定后为该来源的有效已确认预售按原 FIFO/包装规则创建分配与 reserve 流水。使用既有全局 writer gate（SQLite 写锁，其他数据库 LedgerSequence 行锁），到货、确认、取消与出库串行保护。任一预留失败，整个到货事务回滚。
- 到货前创建、到货后才确认的销售草稿，在确认事务中立即预留已到货来源的商品。多个来源分别到货时分别预留，全部可用后才允许整单确认备货。
- 库存分配只表示已预留；prepare_sales_preorder 的订单事件表示拣货确认，二者分开。备货不重复写库存流水；出库必须具有备货事件和完整预留，保留业务日期顺序、幂等及原订单身份。
- 旧备货事件继续有效；历史无来源或旧版本已到货未分配的预售，备货时保留兼容分配路径。不通过迁移补造库存事实，不修改生产数据。
- 库存页沿用现有表格/卡片样式，仅补业务数量：在库、可售、预留、其中预售待备货与已备货。全被预留的商品仍展示。库存账面成本按物理在库的真实剩余成本呈现，不随预留减少；total_stock 保持可售兼容口径。
- 取消释放自动预留；退货恢复库存但不重新建立预售承诺；已预留的来源不能直接撤回到货，须先处理关联订单，并仍受原有“批次完全未使用”撤回限制，取消释放不抹去批次使用历史。
