# Privnote 轻量访问记录

日期：2026-09-13。状态：实现、本地验证和 Kimi 最终独立审查已完成；用户已授权提交并合并至本地 main，未部署。

## 已确认的范围

- 在现有 React Privnote 管理页新增「访问记录」页签，链接列表 → 单条明细。
- 记录访问时间、IP、简化设备及浏览器、成功与失败结果、匿名回访，以及收款二维码放大、复制卡号／收款账号、凭证提交。
- 明细保留 **30 天**；旧 `view_count` 累计次数保留，不从明细反算。
- 使用本站匿名 Cookie 估算同一浏览器的回访；访客编号只在单条链接内有意义。
- Open Design 沿用既有 Claude 配置，不覆盖模型。辅助调查／独立审查按用户最新指令使用 kimi-for-coding / high；主 Agent 负责方案和实现。
- 一期不做 IP 归属地、时长、阅读进度、兴趣分析、图表或新统计平台。

## 页面与统计口径

- 链接列表：标题／token 搜索、类型筛选、分页、历史累计打开次数、近 30 天最近成功打开。
- 明细：时间、匿名访客编号、首次／回访、设备及打开环境、IP、结果／操作。默认客户记录，可查看员工与疑似机器人记录。
- 「成功打开」仅表示内容接口成功返回，不声称已经阅读。需要密码、密码错误、到期、次数用尽、已关闭不计成功。
- 回访次数 = 统计窗口内有匿名标识的客户成功打开次数 − 对应不同匿名标识数；首次也仅指当前统计窗口。员工／机器人不计客户汇总。
- 历史累计和近 30 天明细分开标注；旧链接无明细时明确不能追溯过去的 IP 与设备。
- 复制成功、放大二维码仅代表交互；凭证提交以服务端成功保存为准，不代表到账。

## 最小实现

- 新增一张 `PrivnoteAccessEvent` 表：链接外键、服务端时间、匿名标识、IP、设备名称、浏览器名称、访问者类别、事件、可空去重键。
- 不保存密码、卡号、复制内容、凭证内容、完整请求头或请求体；不维护访客资料表或跨站设备指纹。
- UA 与浏览器自愿提供的设备型号只用于展示。具体型号可识别才展示，否则降级到品牌／设备类别；iPhone 不猜代际或 Pro/Max。
- GET 管理列表和 GET 明细限已认证工作人员；不因知道公开链接 token 就能读取日志。
- 公开交互接口只接受固定事件；绑定成功打开后签发的短期凭据及匿名 Cookie。同一打开内同种操作只记一次，避免重试／重复点击膨胀。
- 凭证提交在后端既有成功分支追加日志，按凭证 ID 去重；不改既有付款幂等流程。
- 访问日志写入失败不阻止客户查看／复制／上传；记录内部错误以便排查。
- 保留现有阅后即焚和查看次数规则，统计不参与可访问性判断；不会为了采集设备或操作再次请求内容接口。
- 仅信任明确配置的反向代理转发 IP；其他情况使用连接 IP，不盲取 `X-Forwarded-For` 的首项。
- 查询固定分页；保留期作为设置项（默认 30 天），提供清理命令及部署调度说明，不引入队列服务。

## 部署接入（本次不执行）

- 先应用新增事件表迁移，再发布引用该表的代码；不补造历史访问明细。
- 每日由已有调度执行 `manage.py purge_privnote_access --apply`，物理删除30天前明细；不带 --apply 只预览。查询即刻按保留期过滤，物理清理依赖调度。
- 当前部署的 Nginx 必须继续覆盖 `X-Real-IP`，Gunicorn 只接受本地 Unix socket；若改成 TCP，设置 `PRIVNOTE_TRUSTED_PROXIES` 为实际直接代理地址。
- 生产匿名 Cookie 使用 Secure 属性，需通过 HTTPS 访问；纯 HTTP 不能可靠关联回访。单次打开的交互凭据有效 24 小时，再次成功打开会签发新凭据；这不缩短链接自身有效期。
- 后续独立任务：一次性链接并发超读。验收应包含两个同时持有旧快照的请求仅一个获得内容、失败请求不消耗名额、无限次收款链接语义不变。
