# 采购来源预售与履约

> 后续规则已调整：取消手动备货，自动预留后直接出库。当前规则见 [直接出库计划](preorder-direct-shipment-plan.md)。以下保留阶段性设计与验证记录。

2026-10-21。基于已提交的分次收款版本 12a4f02。用户授权先发布该版本，再开始本功能；本功能先在独立分支本地实现和验证，不随前一轮自动发布。

## 需求契约

采购草稿/在途商品可创建客户销售草稿，明细类型为预售。来源未到货时确认销售不扣库存；到货时自动预留，来源已到货的草稿确认时立即预留；原销售单支持预收、分次收款，到货后备货、整单出库、尾款以及原有取消/退款/退货。全程保留同一个销售单号，预售来源不因履约完成而抹除。

用户已明确选择：累计确认预售不能超过采购数量；销售草稿不占额度。

## 数据与规则

- SalesOrderItem 增加可空的 source_purchase_order 外键，保留现有商品、销售单位、盒规快照。采购草稿编辑会替换明细，因此不把销售永久挂在易被替换的采购明细 ID 上。来源是采购计划；实际履约批次仍通过 StockAllocation 追溯。
- 来源必须是未删除的草稿或在途采购；按商品、单位和盒规核验，合计确认/已出库的来源明细数量不得超过采购量。确认销售与采购编辑/取消共用写事务门禁和来源采购锁；不只依靠前端校验。
- 已取消/退货销售不占未完成承诺额度。取消销售按现有规则释放备货库存并进入待退款或已取消状态，不自动删除收款。
- 额度表示有效承诺净额：已确认及已出库计入，已取消及已退货释放；重复商品行合并为规范支数计算，不混用盒数和支数。多来源按采购 ID 顺序锁定。新建仅允许草稿/在途来源，既有销售草稿确认时允许来源已经到货。
- 采购草稿修改必须保留已确认预售的商品、单位、盒规以及足够数量；有待履约预售时不能直接取消采购。未确认销售草稿在确认时重新核验来源，避免用过期草稿越过限制。
- 采购到货时按现有 FIFO 和包装规则自动预留已确认预售，来源已到货后才确认的销售单立即预留。明确的“备货”动作确认拣货，不重复扣库存；历史尚未分配的预售兼容在备货时补分配。缺货原子回滚，不负库存。
- 预售类型永久保留；预留从有效库存分配派生，备货从 prepare_sales_preorder 事件派生，不新增可手改库存状态。已备货预售使用原有整单出库、退款和退货逻辑。
- 备货不是收款或会计收入，不改变金额、成本事实或资金余额。新动作记录操作人、Agent 来源、业务日期和幂等信息。API 重放和重复点击不重复预留。
- 已关联预留、备货或出库预售时，禁止撤销来源采购到货，即使 FIFO 实际取用了其他更早批次。备货日期不得早于来源入库和预留日期，出库不得早于备货日期。同键先验证成功动作再检查当前状态，新键重复备货不能再次占用库存。

## 页面与接口

复用采购与销售工作台：采购详情“创建预售单”打开既有风格的销售建单表单；显示来源、采购数量、已确认预售与剩余额度，填写客户、数量和人民币售价。销售详情显示来源及待备货/已备货，备货后沿用出库入口。预售状态和收款状态独立，不建立另一套订单模块。

按仓库要求，在既有 CigarDomTabaka 设计项目中读取品牌规范和采购设计，独立 run 扩展既有采购/销售预览；产品实现复用现有 React 组件和原生 modal。

## 验证与审查

关键场景：采购未付款时建单并收款；额度并发竞争；跨盒规/不存在或取消来源；采购编辑缩量/删项/取消保护；来源到货前不能备货；备货幂等和缺货原子回滚；混合单不重复预留现货；取消释放；预收→出库→尾款/退款/退货金额与库存守恒；历史无来源预售兼容；新增字段迁移不改变历史事实。前端覆盖建单字段、额度、错误提示、备货与出库按钮和来源保留。完成实现期间及最终独立审查。

自动预留的补充规则与验证见 [到货自动预留计划](preorder-arrival-reservation-plan.md)。
