# 销售分次收款

2026-10-21。初始范围为本地实现、验证与独立审查；后续用户授权提交并发布本轮改动，发布走准确提交的 CI → Deploy 流程，不补录真实交易。

## 需求契约

同一销售单允许多次人民币收款，可使用不同公司账户和实际到账日期。每笔金额必须为正、精确到分，累计不能超过订单应收。累计和剩余由未撤回的正式收款派生，不增加可手工修改的余额字段。新增 partial 收款状态，履约独立。

人工核实沿用现有核实弹窗和确认收款弹窗的样式与交互，填写实际金额、明确账户和日期后确认；不重新设计布局或视觉。截图不自动记账。部分核实后可继续上传后续付款凭证；同一凭证只能核实一次。

## 会计与兼容

- 移除每单一笔有效收款和每单一条 accepted 凭证的唯一限制；保留幂等、pending 唯一、账务不可变约束。
- 出库前的每笔收款记预收，出库时分别结转已预收和剩余应收；出库后的收款冲减应收。出库重放只看出库流水之前的有效收款。
- 取消或整单退货后，仅退累计实收，按每笔原账户和原科目汇总退回，一次原子事务。沿用一张 SalesRefund 汇总事实；多个原账户时 fund_account 为空，实际账户金额来自退款分录。单账户历史记录保持不变。
- 撤回只处理最新有效收款，保留现有尚未出库、没有后续正式流水或对账的限制，撤回后重算收款状态。
- 业务日期不得使预收晚于出库、出库后收款早于出库、退款早于对应业务。无法安全跨履约补录时明确报错，不伪造日期。
- 待收汇总只计剩余金额；客户付款页区分订单总额、已收和剩余，部分到账不显示整单成功。
- 不支持超收、客户储值、分次退款或部分出库；历史流水不重写。
