# 销售收款撤回与重新收款

## 目标

工作人员误选收款账户时，允许在没有后续业务依赖的前提下撤回原收款，再按实际到账账户重新记录。原收款和冲正流水必须保留，不能直接修改或删除。

## 业务规则

- 只有已确认、尚未出库且当前为已收款的销售单可以撤回收款。
- 原收款之后，全部资金账户不能存在任何其他已入账流水；订单也不能存在出库、退款、退货或人肉成本事实，原收款账户不能存在已确认的后续对账。
- 撤回日期不能早于原收款日期，必须填写原因，并保留操作人和幂等键。
- 撤回追加原收款的反向账务流水，把订单恢复为“待收款”；库存预留、履约状态、商品收入和利润不变。
- 原 `SalesReceipt` 标记为已撤回并永久保留。重新收款创建新的 `SalesReceipt`，允许选择实际到账账户。
- 原收款幂等键的重放只返回当次历史收款，不会再次入账，也不会改变当前订单的收款状态；重新收款必须使用新的幂等键。
- 月报按业务日期分别记录原收款和撤回冲正：同月净额抵销，跨月分别落入原月份与撤回月份；经营累计只统计未撤回的有效收款，付款凭证仍保留对历史收款的引用。
- 退款只能使用当前有效收款，不得引用已经撤回的历史收款。

## 交互

- 已收款且满足订单状态前提时显示“撤回收款”。后台仍会再次检查所有后续正式流水，检查失败时拒绝。
- 点击“收款”填写金额、日期和账户后，增加第二次确认弹窗，明确显示订单、金额、业务日期和到账账户，确认后才正式入账。

## 发布和数据修复

先完成迁移、测试和发布，再通过订单页面撤回错误收款并重新收款。生产数据库不做直接字段修改。
