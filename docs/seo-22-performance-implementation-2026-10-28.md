# SEO-22：首屏性能优化实施

日期：2026-10-28 UTC。状态：本地实现与验证完成；用户已授权发布，CI/CD 执行中。承接 [PageSpeed 报告复核](seo-22-pagespeed-review-2026-10-28.md)及 [SEO 总计划](seo-roadmap.md)。

## 范围与工作区

用户同意五项优化，要求启动动画只做适度提速，并修复刷新时年龄提示覆盖动画。本轮保留现有视觉、公开预渲染内容、页面刷新与撤回/404 行为；实现加载协调、地图延迟、响应式图片、首屏依赖精简和报告中具体对比度问题。没有重新设计页面或修改商品资料。

实现基于已核对的生产版本 `b4a108b65f2e0bee86726f96c39a26f1b5b3abf6`，分支 `feat/seo-22-performance`，工作区 `/tmp/cigar-seo22-performance`。原目录 `/home/jason/moscow_cigar` 的分支和已有未提交工作保留，SEO 文档同步更新。

## 实现

1. **启动与年龄确认**：保留 2,580 ms 原动画周期和 400 ms 飞入页头效果，将页面和 Logo 已就绪后的剩余周期等待上限设为 1,800 ms。启动期间正文设为 inert，年龄提示保持隐藏且不捕获焦点；动画完成后恢复原可访问状态，再显示需要的年龄确认。已确认年龄的刷新不再短暂聚焦年龄按钮。减少动态效果、Logo 回退、加载失败及重新加载行为保留。
2. **地图**：SSR 不设置 iframe 的 `src`。年龄确认与启动完成后，在地图进入距视口 200 px 范围时加载；无 IntersectionObserver 时按滚动和尺寸变化检查。保留地图占位、门店地址与外部路线链接。地图实际打开后的第三方 Cookie 仍由 Yandex 提供。
3. **图片**：五张既有首页图生成 320/480/640/800/原宽 WebP，按布局和像素密度选择；只有第一张保持高优先级自动预加载，其余延迟。页头 Logo 使用 176 px 版本，动画静态回退/飞入用响应式版本。原图、商品外观和布局保留。
4. **首屏依赖与请求**：把仅员工/旧 SPA 路由需要的 React Router 匹配 helper 从公共偏好模块分离，路由规则不变。认证检查推迟至启动完成；默认 RUB 不请求参考汇率，切换 CNY/USD 时读取并复用有效数据。页面状态更新请求仍立即执行，保留撤回、404 与元数据更新。
5. **对比度与渲染一致性**：报告对应的年龄说明、俄语/英语切换链接使用更深的同色系文字。修复实际 hydration 核查发现的轮播和微信卡片 ID 差异，让 SSR 与客户端的无障碍引用一致。已有静态压缩和缓存继续使用，未把 HTML 或动态接口改为长期缓存。

## 构建与部署准备

新增 `frontend/scripts/generate_responsive_assets.py`，复用 Pillow：先校验五个原图和尺寸，暂存派生文件，再逐文件原子替换并最后写清单。清单记录来源路径、SHA-256、Pillow 版本和导出参数。重复生成结果一致，原图不修改，生成媒体与构建文件不提交 Git。

CI 构建前生成 Logo，并用临时图片验证五图转换、透明通道、缺图失败和幂等。前端交付包检查新增 Logo 是否齐备。部署工作流先从服务器既有媒体生成五图，成功后才安装新前端；失败会终止，不安装引用缺图的新前端。现有页面缓存与 sitemap 刷新步骤保留。本轮只修改流程，没有运行生产部署。

## 测量结果

### 构建和传送

基线和候选使用同一依赖及构建工具，递归统计 Storefront 入口的静态依赖，同一 Python gzip 压缩口径：

| 项目 | 基线 | 候选 | 变化 |
| --- | ---: | ---: | ---: |
| 首屏 JavaScript | 106,700 B | 93,091 B | 减少 13,609 B，约 12.8% |
| 首屏 CSS | 13,117 B | 13,137 B | 增加 20 B |
| 手机 390 px、DPR 2 实际选择的五张首页图 | 89,274 B | 33,202 B | 减少约 62.8% |
| 同一手机样本的静态 Logo 请求合计 | 92,156 B | 57,464 B | 减少约 37.6% |

静态 Logo 候选统计包含页头 176 px 和飞入时 376 px 两张；动态 SVG 保持不变。高像素密度或更宽视口会选择更大图片，因此不将手机样本节省量套用到所有设备。报告的约 149 KiB 是 Lighthouse 估算，本轮按实际选择资源记账。共享 `NotFoundPage` 构建块仍有公共运行时用途，没有按文件名删除。

### 浏览器对比

使用本地基线/候选预览服务器、相同公开页面 payload、Chromium 144、390×844、DPR 2、150 ms 延迟、200,000 B/s 下载、4 倍 CPU 限速、禁用浏览器缓存。每版本首次/已确认各三次，共 12 次；[逐次数据](seo-22-local-measurements-2026-10-28.csv)。两组同样拦截 Yandex 请求，以观察第一方加载和地图启动时机；该组没有测量地图下载后的总流量或 PSI Speed Index。

| 中位数 | 基线首次 | 候选首次 | 基线已确认 | 候选已确认 |
| --- | ---: | ---: | ---: | ---: |
| app-ready → 动画退出 | 3.22 s | 2.72 s | 3.18 s | 2.82 s |

就绪到交接时间缩短，导航到退出的总耗时在本轮没有改善；候选 app-ready 更晚且单次波动明显。当前可确认的收益是传送减量、消除年龄遮挡/抢焦点和延后地图，暂不宣称整体 PageSpeed 分数或核心网页指标已提高。发布后需在相同地区、设备与年龄状态复测。

旧版首次样本均观察到年龄层与启动退场同屏，已确认刷新也捕获到一次年龄按钮提前聚焦。候选六个首页性能样本及另外八个俄/英首页、俄语品牌/商品浏览器场景中，此类重叠和提前聚焦均为零。候选首屏 Yandex 请求为零；确认年龄并滚动到联系区后 iframe 正常设置地图地址。三语页面、微信焦点和引用关系通过。

本地首次访问 Lighthouse 13.5.0 的 accessibility 单项复测为 **100**，`color-contrast` 通过；旧版同类检查的三个失败节点是年龄说明与两个语言链接。此项只记录本地首次访问状态，不代替上线后的全页面报告。
