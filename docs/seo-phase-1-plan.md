- 门店页突出真实经营身份和地点，保留俄文地址以便复制导航，中文补充到店说明。地图必须指向核实后的商家，不仅链接到泛地址搜索。

## 技术方案

### React 公开页面预渲染

建议采用构建阶段生成重点公开页面 HTML 的方式，保留 React 组件及后续交互，内部业务功能继续使用 SPA。不新增 Django 产品模板，不进行整体框架迁移。

这扩展了 [ADR 0006](adr/0006-django-react-混合架构.md) 中“统一空入口”的现状。已完成品牌页构建验证，并在 [ADR 0019](adr/0019-public-catalog-prerendering.md) 记录 React 构建阶段预渲染与私有 HTML 安装方案。

1. 建立重点公开页面清单，统一记录语言、规范 URL、内容来源、元数据和等价翻译页关系。
2. 用已核验、字段白名单化的公开目录快照和编辑文案生成 HTML。构建输入有版本和来源，构建不依赖生产登录态或每次实时请求生产站点；本地开发明确使用 DEBUG 和开发数据库。
3. 快照仅含公开品牌、型号、规格和图片引用。禁止打包客户信息、库存批次、成本、账务、内部报价、token 或认证信息。文案与非敏感配置可以版本管理，数据库和生成的 HTML 构建产物不提交。
4. HTML 由现有 React 页面组件生成，用户和搜索引擎接收相同公开正文。React 接管时复用同版本初始数据，避免先删除正文再等待 API；不按爬虫 User-Agent 提供独立内容。
5. 去除重点公开页对登录检查和启动遮罩的正文阻塞。关闭 JS 时正文和主要链接仍然可见；仅在 HTML 中存在但被 `opacity:0` 或遮罩隐藏不算通过。
6. 已有目录页逐步接入同一元数据规则；未预渲染的有效页面保持现有功能，不返回错误的 404。
7. 内容修订时重新构建。页面、资源和清单按版本一起发布，失败构建阻止发布；需要撤回时整体回到上一发布版本。实体删除、资料撤回后不得继续从静态快照返回已失效内容。

具体构建工具和数据快照产生方式在单页验证中决定；若必须引入常驻 SSR 服务、全站迁移或业务模型变更，应先报告范围变化，不悄悄扩大第一期。

### URL 和响应规则

建议规范主域名保留 `https://cigardomtabaka.com`。域名、协议及尾斜杠跳转只针对适用页面设计，避免影响 API POST、上传和 token 请求语义。

| 请求 | 预期处理 |
| --- | --- |
| 有效重点公开页 | 200，页面专属正文与元数据 |
| 其他已有有效目录页 | 保持访问和功能；元数据逐步统一 |
| 有效型号 ID 的旧 slug 或省略 slug 链接 | 重定向到同一实体的规范地址，不按错误 slug 生成新页面 |
| 不存在的品牌、型号、未发布语言页或路径 | 真实 404 和可用错误页，不返回首页 200，不伪造翻译页 |
| 数据源暂时故障 | 返回合适错误或可确认有效的已发布版本，不能把故障误判为实体不存在 |
| `/robots.txt` | 有效纯文本规则，标明 sitemap，允许所需公开 JS、CSS、图片 |
| `/sitemap.xml` | 有效 XML，仅列允许索引、200、规范的公开页面；lastmod 反映真实更新 |
| 登录及业务页面 | 保持既有访问控制；页面壳不参与索引，后端 API 权限不放宽 |
| `/p/:token` 等客户专属页面 | 首次响应即排除索引，保留既有授权、有效期和访问语义，不进入 sitemap |

路由判断须在通配 SPA 返回前区分公开页、业务页、静态资源和真实不存在地址。现有 API 对不存在品牌或型号的响应也要检查，避免目录页面把 500 当 404 处理。

`robots.txt` 控制抓取，不能充当认证或可靠的去索引措施。依靠 `noindex` 排除的可访问页面需要允许机器人读取该指令；不设计先全面 Disallow、再期待机器人读取页面 noindex 的冲突配置。私密数据继续由后端权限保护。

### 元数据与语言

每个公开页面有自己的 title、description、H1 和 canonical。规范页指向自己，不将全部品牌、型号或翻译页 canonical 到首页。模板只使用同一份元数据来源，避免初始 HTML 和 React 路由切换后出现冲突。

中文、俄文、英文页面分别声明对应 `lang`。只有已上线、内容等价且返回 200 的页面才互设 `hreflang`，包含自身和对方；可用 `x-default` 指向默认版本。不把缺失译文链接到首页，也不根据 IP 或浏览器语言强制跳转。Yandex 的语言关系使用 HTML 标记，不能只写在 sitemap。[Google 多语言指南](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)、[Yandex 多语言指南](https://yandex.com/support/webmaster/en/yandex-indexing/locale-pages)。

优先使用与可见资料一致的 Organization 或 LocalBusiness、WebSite、BreadcrumbList 结构化数据，并校验格式。不得编造评分、价格、库存或营业时间。Google 对烟草 Product 富结果有限制，本期不以商品富结果或购物 Feed 为交付目标。[Google Product 内容规则](https://developers.google.com/search/docs/appearance/structured-data/product-snippet)。

## 验收标准

- 重点 URL 在未登录、关闭 JS 的情况下显示正文、标题和可用主要链接；JS 开启后无 hydration 错误，目录查询和路由切换正常。
- 手机和桌面可访问品牌、型号、联系和语言入口；公共内容不等待用户登录检查或全屏启动动画结束才出现。
- robots 为纯文本，sitemap 为可解析 XML；sitemap 无私密 token、业务页、重定向页、404、noindex 页或不存在的语言版本。
- 正确规范化 www、协议、适用的尾斜杠及型号旧 slug，无循环跳转；品牌不存在、型号不存在和未知路径返回真实 404。
- 页面 title、description、canonical 和语言关系在原始 HTML 与客户端切换后保持一致；所有 hreflang 目标有效且相互对应。
- 私密文档首次响应排除索引；未登录和非工作人员无法通过 HTML 快照、缓存或 API 取得受保护数据。测试使用测试 token，不打开真实客户一次性文档。
- 构建快照和输出通过公开字段检查，不能包含成本、库存批次、客户、收付款和认证信息。构建失败不会发布半套 HTML 或资源。
- 品牌和型号资料核验完成；没有把目录收录误标现货，没有虚构资质、评价、盒规和营业时间。
- 完成受影响后端测试、`manage.py check`、前端 typecheck、lint、相关 Vitest 和 build；针对 URL、无 JS 正文、错误路径和访问边界做有价值的回归验证。
- 未来上线后，Yandex 和 Google 的实际 URL 检查能读取重点内容；地图卡片、网站链接和门店事实一致。索引和排名属于观察结果，不作为代码正确性保证。

## 度量与复盘

上线前记录重点 URL 的收录状态、已有查询、曝光和点击；数据不可取得时记录“未知”，不能写成零。上线后按中文、俄文、英文及搜索引擎分开观察，每 28 天复盘，第一周优先检查抓取错误。

网页搜索关注目标页是否被发现、索引状态、非品牌词曝光、点击及落地页匹配。地图关注发现流量、网站点击和平台实际提供的电话或路线互动。网站如增加联系按钮事件，应限于公开页、记录事件类型和页面，不采集消息内容、客户身份或私密 token；新增分析服务与账号配置在实施时明确选择，不默认为全站接入。

验收不承诺“若干天进前十”。若页面未被收录，先诊断抓取、重复与内容质量；有曝光无点击时检查标题与意图；有访问无联系时检查门店可信度、资料和联系路径。后续动作由这些结果决定。
