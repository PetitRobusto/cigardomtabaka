# 商城与管理应用整合

同一 Django 项目和会话下，站点根路径 `/` 为商城，`/ru/`、`/en/` 为语言入口。商城启用仍由 `STOREFRONT_ENABLED` 控制；此改动不自动开启生产开关。

游客和普通账号只看到商城。后台入口统一收进原风格导航的“管理工具”，仅工作人员可见；服务器页面和内部目录、价格 API 同时验证工作人员权限。完整资料库移至 `/library`。移动底部管理导航仅工作人员可见。原有客户 Privnote token 链接继续公开。

商城保留补充导航、品牌筛选、币种切换和 B2 商品图片布局，搜索并入顶部导航；商城与管理页复用完整原版页脚。首次加载使用原启动动画，商城内部切换继续使用 SPA。

语言菜单保留当前商品及筛选参数，并保存语言偏好。缺少译文时回退至英语或正式商品字段，商品不会因为缺译文消失；缺译文的页面不进入搜索索引或 hreflang 列表。未添加品牌介绍。

## 本地数据准备

`DJANGO_DEBUG=True` 下先执行迁移。`prepare_storefront_localizations` 默认只预览：依据已审核图片清单逐项核对 60 款商品的品牌、英文名称和发行信息，补充原有型号及规格的三语展示。

只有明确传入 `--apply` 且 DEBUG 开启、数据库不是 `cigars.db` 时才写入。保留现有商品及品牌翻译；首页仅可发布与既有模板完全相同的草稿。品牌正文留空。它不修改商品、库存、价格、订单、会计或图片记录。

构建前端后执行 `render_storefront`，持续刷新使用 `render_storefront --watch`。开发环境通过 Django 入口访问，管理页 Vite 来源需与该入口配置相符；直接打开未配置的 Vite 页面不会循环跳转。
