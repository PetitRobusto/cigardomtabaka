# 经营工作台、订单中心与 Day 1 初始化设计

- 日期：2026-08-13
- 状态：待用户书面审阅
- 设计基线：已确认的 Visual Companion 交互原型
- 适用对象：两位内部经营人员

## 1. 目标

本次调整把日常查看、销售操作和首次建账拆成边界清楚的流程：

- 数据工作台只展示经营数字、账户、利润和对账提醒。
- 订单中心独立承担销售单创建、查询和状态推进。
- Day 1 初始化只用于生产环境首次建立期初事实，不作为常用功能。
- 使用帮助按真实工作流讲解完整操作，而不是只列字段说明。
- 顶部和手机导航移除 Django Admin 的“管理”入口；`/admin/` 技术路由不删除。

## 2. 信息架构与路由

### 2.1 常驻入口

| 路由 | 导航名称 | 职责 |
|---|---|---|
| `/accounting` | 账务 | 数据工作台、账户余额、月度利润、对账与日常账务动作 |
| `/sales` | 订单 | 销售单统计、查询、创建与状态推进 |
| `/help` | 帮助 | 完整业务流程、功能参考和页面引导 |

现有 `/sales#accounting` 不再作为正式入口；前端将其兼容重定向到 `/accounting`，避免旧书签和旧引导失效。

### 2.2 Day 1 非常驻入口

Day 1 使用独立受保护路由 `/accounting/day1`，但绝不出现在桌面主导航、手机底部导航或普通“常用功能”列表中。

- 尚未初始化：`/accounting` 顶部显示一次醒目的“完成 Day 1 初始化”待办卡，只有这里提供入口。
- 已有共享草稿：待办卡显示进度和“继续初始化”。
- 初始化成功：待办卡和入口永久消失；直接访问 `/accounting/day1` 时显示只读完成摘要并返回账务工作台，不能再次提交。
- 初始化完成后的纠错只能使用正常库存调整、账户调整或冲正流程，不能重开 Day 1。

## 3. 数据工作台

数据工作台最上方首先展示核心统计：人民币资金合计、库存账面成本、本月净利润、待收订单金额。下方展示：

- 四类公司资金账户的原币余额及外币人民币账面成本。
- 当月销售收入、销售成本、客户人肉费收入和实际人肉成本。
- 最近对账状态、逾期未对账提醒和进入对账动作。
- 日常会计动作入口，例如换汇、费用、采购付款和分红；销售单不在此创建或查询。

工作台只读取账务和销售汇总接口。初始化未完成时，依赖可信期初余额的经营指标显示“等待初始化”，不能用零值伪装成真实结果。

## 4. 订单中心

### 4.1 页面结构

订单中心顶部展示草稿、已预留、待收款和本月完成四组统计。主体分为独立的创建区与订单查询列表；桌面可并排，手机按“创建入口、状态筛选、订单列表”自然纵向排列。

订单查询支持订单号、客户、履约状态和收款状态筛选。订单动作继续使用后端现有状态机；前端隐藏按钮不能代替后端合法转换校验。

### 4.2 库存 autocomplete

“添加雪茄”输入框获得焦点时立即请求并展示有可售库存的雪茄，不要求先输入两个字符。输入文字后使用现有搜索规则缩小结果。

每个结果至少显示：

- 品牌与雪茄名称。
- 可售整盒包装及盒数。
- 可售散支数（作为次级信息）。
- 适用时展示批次成本参考，但不允许用户用搜索结果修改成本。

选择商品后，整盒为默认销售单位；散支仍是次级选择。提交时后端重新校验库存，因此联想结果只用于选择，不能构成库存承诺。

### 4.3 人肉费承担方式

销售草稿新增明确字段 `transport_payer`：`customer` 或 `company`。

- 客户承担：允许填写非负的客户人肉费，计入订单应收；该金额在确认订单时冻结。
- 公司承担：客户人肉费强制为 0，前后端都拒绝非零金额。
- 两种方式都不要求创建订单时知道实际人肉成本。
- 实际人肉成本在履约后按真实发生金额，从一个人民币公司账户单独记录；它可以与客户人肉费不同。

商品金额、客户人肉费和订单应收在表单底部即时分开展示。

## 5. Day 1 初始化

### 5.1 状态和唯一性

新增单例式初始化记录，状态只有：`draft`、`completed`。

- 两位经营者编辑同一个共享草稿，不按用户各建一份。
- 草稿保存不创建资金账户、账务流水、库存批次或余额缓存。
- 最终确认必须在一个数据库事务中完成。
- 数据库层和服务层同时保证只能存在一次成功初始化；并发提交中只允许一个成功。
- 成功记录保存启用日期、确认人、确认时间和不可编辑的期初摘要。

如果系统已经存在非 Day 1 的正式账务流水或不符合初始化前提的库存事实，最终确认必须拒绝并明确列出冲突，避免在已有经营事实前插入虚假期初。

### 5.2 四步向导

1. **范围确认**：选择启用业务日期，说明只迁移今天实际拥有的公司资产。
2. **公司账户**：创建“我的人民币账户”“合伙人人民币账户”“卢布银行卡”“USDT 账户”四个默认槽位；名称可在草稿中修改。
3. **期初库存**：只从现有雪茄目录选择商品，逐包装录入整盒数、每盒支数、散支数和估算每支人民币成本。
4. **核对生效**：展示账户、余额、库存数量、库存成本和自动计算的期初投入资本，二次确认后原子生效。

### 5.3 账户录入

- 两个 CNY 账户：输入人民币实际余额。
- RUB 账户：输入卢布实际余额和该余额的大概人民币账面成本。
- USDT 账户：输入 USDT 实际余额和该余额的大概人民币账面成本。
- 所有余额与成本必须非负；原币余额为 0 时人民币账面成本必须为 0，反之亦然。
- 首版不允许在 Day 1 增加第五个账户；初始化后可走正常账户管理能力扩展。

### 5.4 期初库存批次

每个“雪茄 + 包装规格”创建一个独立期初库存批次：

- 数量 = 整盒数 × 每盒支数 + 散支数。
- 人民币成本 = 数量 × 估算每支人民币成本。
- 记录来源为 Day 1，不伪造采购单、卢布付款、换汇或历史到货日期。
- 同一雪茄和相同包装规格在草稿中只能出现一行。
- 至少一个整盒或一支散支，成本必须大于零。

### 5.5 期初会计结果

最终确认一次性创建：

- 四个公司资金账户及其期初余额。
- RUB 和 USDT 的人民币账面成本。
- 所有期初库存批次及库存人民币成本。
- 对应的平衡期初账务流水。
- 期初未分配利润固定为 0。
- 剩余净资产全部计入期初合伙人投入资本。

首版明确不迁移历史未收销售款、客户预收、在途采购、未付旧费用或历史利润。

## 6. 使用帮助与引导

帮助中心按流程而非模块名称组织快速开始，至少包含：

1. 首次 Day 1 初始化。
2. 人民币或 USDT 换入卢布并完成采购。
3. 从报价信息人工创建销售草稿。
4. 从可售库存添加商品、选择整盒/散支、填写售价。
5. 选择客户或公司承担人肉费。
6. 确认订单、预留库存、出库和一次性人民币收款。
7. 记录实际人肉成本、日常费用、完成对账并查看月利润。

“完整创建一张销售单”提供逐步章节和跳转到真实页面的按钮。引导只高亮并解释真实控件；不得为了演示自动确认订单、预留库存或写入生产数据。

初始化完成后，帮助文档仍可阅读 Day 1 规则，但不再提供可提交入口，只能查看完成摘要。

## 7. API 与后端边界

新增或调整的 API 分为四组：

- 初始化状态：读取 `not_started`、`draft` 或 `completed` 以及待办摘要。
- 初始化草稿：读取/保存共享账户和库存草稿；使用版本号防止两位操作者静默覆盖彼此修改。
- 初始化确认：校验完整草稿，以幂等键和数据库锁执行一次原子确认。
- 工作台汇总：单独提供账户、库存成本、应收、对账和月利润摘要，不让前端从大批明细自行拼算财务数字。

所有接口仅允许已登录 staff。金额使用字符串形式的精确十进制；业务日期按莫斯科日期处理。后端错误返回可定位到具体步骤和字段。

销售创建 API 增加人肉费承担方并保持旧调用兼容：旧请求若仅有非零客户人肉费则推断为客户承担；仅有零金额则推断为公司承担。数据迁移为既有订单补齐明确值。

## 8. 失败与恢复

- 草稿保存失败不丢失当前页面录入，前端明确提示重试。
- 共享草稿版本冲突时拒绝覆盖并要求刷新查看对方最新修改。
- 库存目录项失效或重复包装时，最终确认前阻止提交并定位到问题行。
- 最终确认任一账户、流水或库存创建失败时整体回滚，状态仍为草稿。
- 重复确认或并发确认返回同一个完成结果，不重复生成期初资产。
- 工作台某一统计接口失败时保留其他区域，失败区域单独提示，不能把失败渲染为 0。

## 9. 测试与验证

### 9.1 后端

- Day 1 草稿的创建、共享编辑、版本冲突和权限。
- 四类账户余额/账面成本校验。
- 期初库存包装数量、重复行和成本计算。
- 最终确认的原子性、幂等性、并发唯一性和初始化前提检查。
- 期初流水平衡、外币成本、库存成本和投入资本守恒。
- 初始化后不可重跑，只能读取完成摘要。
- 人肉费承担方式及公司承担时金额必须为 0。
- 旧销售数据迁移与 API 兼容。

### 9.2 前端

- 主导航和手机导航均无“管理”及 Day 1 常驻入口。
- `/sales` 与 `/accounting` 页面职责分离，旧 hash 正确重定向。
- 统计卡位于页面内容最上方。
- 雪茄输入框聚焦即展示可售库存，输入后筛选，选择后可创建订单。
- 人肉费切换正确影响客户收费和订单合计。
- Day 1 四步草稿、版本冲突、最终确认和完成态守卫。
- 帮助中心完整销售流程、页面跳转及只读演示安全性。

### 9.3 完成验证

- Django migration 检查、`manage.py check` 和相关后端测试。
- 前端单元测试、lint 与生产构建。
- 桌面和手机真实浏览器检查：工作台、订单创建、库存联想、Day 1 各步骤、帮助流程。
- 使用开发数据库完整演练一次初始化；不得对生产数据库执行测试初始化。

## 10. 明确不做

- Day 1 Excel/CSV 导入。
- 历史采购批次或历史换汇重建。
- Day 1 迁移未完成历史业务。
- 多次或按用户分别初始化。
- 在 Django Admin 编辑初始化数据。
- 自动把报价视为成交或自动创建销售单。
- 分期收款、多币种销售收款或卢布销售收款。
