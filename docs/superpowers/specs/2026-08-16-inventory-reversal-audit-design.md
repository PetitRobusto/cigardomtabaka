# 库存反向动作与一致性审计设计

**状态：** 已确认，进入实现
**范围：** 后端反向动作与库存审计；不包含预售、前端和 Help

## 目标

在不删除原业务事实的前提下，为采购到货、销售出库和库存调整提供明确的整单或整次反向动作，并提供只读的全量库存一致性审计。

## 账务冲正

- 原账务交易保持 `posted`，原分录继续参与历史余额。
- 冲正动作新增一笔同业务类型、金额完全相反的 `posted` 交易；`source_type=ledger_reversal`，`source_id` 指向原交易。
- 原交易的 `reversed_by` 指向冲正交易。冲正交易本身不可再次冲正。
- 不使用现有 `reversed` 状态；当前报表会排除该状态，改状态后再记反向分录会造成双重冲正。
- 冲正使用独立幂等键，重放必须核对原交易、业务日期、操作人、原因和全部反向分录。

## 撤销采购到货

- 按采购单整单撤销，不允许只撤销一条采购明细。
- 仅当该次到货的全部批次仍保持原始数量、包装形态和成本池，且没有库存分配、销售、拆盒或调整时允许撤销。
- 原批次保留，标记已撤销并把可售、物理数量及剩余成本池归零；新增负数 `reverse_receive` 流水。
- 采购到货账务交易生成反向交易，采购单回到 `in_transit`，采购明细实际成本清空；之后可用新幂等键再次整单到货。

## 整单销售退货

- 只允许对已出库且尚未退货的销售单执行整单退货，不支持部分退货。
- 所有 `fulfilled` 分配转为 `returned`，按原批次和原包装形态恢复物理库存、可售库存和成本池，并减少批次累计销售成本。
- 新增正数 `return` 库存流水和 `SalesReturn` 事实；原销售出库事实保留。
- 原销售出库账务交易生成反向交易。订单履约状态变为 `returned`；已收款订单进入 `refund_pending`，未收款订单保持 `unpaid`。
- 退款仍是独立资金动作。退款科目根据原收款冲销的是应收款还是客户预收款确定。
- 已记录的人肉实际成本不冲回，因为该费用已经真实发生。

## 撤销库存调整

- 新增结构化 `InventoryAdjustmentAction`，记录每次调整的数量、形态、成本、批次明细、原账务交易和操作人。
- 只允许整次撤销。正向调整若已有任一新增库存被占用则阻止；负向调整只有在恢复后不破坏包装和数量约束时允许。
- 撤销按原动作逐批反向更新数量和成本，新增 `reverse_adjustment` 流水，并冲正原库存调整账务交易。
- 旧数据没有结构化动作事实时只可审计，不允许猜测后撤销。

## 一致性审计

审计为只读操作，返回问题列表，不自动修数据。至少校验：

- 批次总支数与盒/散支形态一致，可售不超过物理，所有数量和成本非负。
- 成本守恒：原始成本加正向调整成本，等于剩余成本、销售成本、损耗成本和撤销成本之和。
- 活动分配数量与批次 `physical - available` 的预留差额一致。
- 分配状态与 reserve/release/ship/return 流水一致。
- 已撤销到货、已退货销售和已撤销调整都存在完整的库存流水与账务反向关联。

## 安全边界

- 所有写动作使用统一 SQLite writer gate、整事务 retry、真实操作人和独立幂等键。
- 任一阻断条件失败时，库存、业务状态与账务分录整笔回滚。
- 普通 ORM 仍不能修改库存事实或终态账务事实。
